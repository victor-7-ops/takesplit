# Decisions Log

- **2026-09-16** — Adopted the clip confidence score feature (see `docs/superpowers/specs/2026-09-16-clip-confidence-score-design.md`) into Phase 0/4 of the base plan, rather than treating it as a later add-on. Reason: it's cheap to add while writing `detect.py` for the first time, expensive to retrofit once clip schema and UI are built around a binary auto_detected flag.
- **2026-09-16** — Confidence data stored in `rehearsals.detection_params` jsonb rather than a new `clips.confidence` column. Reason: avoids a schema migration for a display-only, non-authoritative value; accepted tradeoff is no SQL-level filtering across clips by confidence tier at MVP scale.
- **2026-09-16** — Skipped the Phase 0 acceptance gate (real-recording accuracy run against HANDOFF.md §3 target) and started Phase 1 immediately, at Victor's explicit request, overriding the "don't start a phase until the previous phase's acceptance passes" rule in CLAUDE.md. Risk accepted: `detect.py`'s default params (`threshold_ratio`, `min_gap_sec`, `min_take_sec`, `pad_sec`, confidence weights) are untested against real rehearsal audio and may need retuning once real recordings are run — that retuning is isolated to `DEFAULT_PARAMS` in `detect.py` and doesn't affect Phase 1's schema/RLS work.
- **2026-09-29** — `band_members_insert` RLS policy (in `supabase/migrations/0002_rls.sql`) only checks `user_id = auth.uid()`, with no DB-level check that the joining user actually knows the band's `invite_code`. Any authenticated user can currently self-join any band by guessing/enumerating its UUID — invite-code validation exists only in the app layer's join flow, not enforced at the database boundary. Accepted as-is for Phase 1 (schema/RLS review, not app code) since the MVP's client never exposes a raw insert path. **Must fix before Phase 5** (band collaboration ships): convert the join flow to a `SECURITY DEFINER` RPC (e.g. `join_band(p_invite_code text, p_display_name text)`) that validates the invite code server-side before inserting, so the raw `band_members` insert is never independently reachable.
